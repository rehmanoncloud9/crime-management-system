Algorithm

ER to Relational Mapping

Junction Tables

The connection between a Case and an Officer is many to many. We mapped this using a bridge table called case_officers with keys for both sides.

Weak Entities

Some records like evidence logs cannot exist without a parent. We used cascading rules to make sure they are removed if the parent is deleted.

Step 1

First Normal Form : Atomicity

Unnormalized Data

Incident[ID, Title, SuspectsList]

The SuspectsList column contains multiple names like "John, Mike, Sarah". This makes it very hard to search for a single person.

1NF Compliance

Incident[ID, Title]
IncidentSuspects[IncidentID, PersonID]

Now every piece of data is atomic. We use a separate table to link suspects to incidents which allows for easy searching.

Step 2

Second Normal Form : Full Dependency

Partial Dependency

OfficerTask[BadgeNum, TaskID, OfficerName]

In this table the OfficerName only depends on the BadgeNum and not the TaskID. This is a partial dependency.

2NF Compliance

Officer[BadgeNum, Name]
OfficerTask[BadgeNum, TaskID]

We moved the officer details to their own table. Now every non key attribute depends on the entire primary key.

Step 3

Third Normal Form : Transitive Removal

Transitive Dependency

Location[AreaID, AreaName, CityName, ProvinceName]

Here the ProvinceName depends on the CityName which depends on the AreaID. This chain creates data redundancy.

3NF Compliance

Area[AreaID, Name, CityID]
City[CityID, Name, ProvinceID]
Province[ProvinceID, Name]

By breaking these into separate levels we ensure that a change to a province name only happens in one single place.

Advanced Concepts

Analytical Views

CREATE VIEW v_active_cases AS
SELECT cf.case_number, ci.title,
  CONCAT(p.first_name, ' ', p.last_name) 
  AS investigator,
  DATEDIFF(NOW(), cf.opened_at) 
  AS days_open
FROM case_files cf
JOIN crime_incidents ci ON ci.id = cf.incident_id
WHERE cf.status NOT IN ('CLOSED');

Why we use Views

We use views to create a virtual table that brings information from many different places together. This lets our application see a simple list of active cases without needing to write complex joins every time.

Business Logic

Integrity Triggers

CREATE TRIGGER trg_warrant_not_expired
BEFORE INSERT ON arrest_records
FOR EACH ROW
BEGIN
  IF EXISTS (
    SELECT 1 FROM warrants 
    WHERE id = NEW.warrant_id 
    AND expires_at < CURDATE()
  ) THEN
    SIGNAL SQLSTATE '45000'
    SET MESSAGE_TEXT = 'Expired warrant';
  END IF;
END;

Data Layer Protection

Triggers act as a final guard for our data. Even if the application fails a check, the database itself will block an arrest if the warrant has expired. This ensures our records are always legally valid.
